# Neighbourhood base-map tiles (Protomaps PMTiles)

The `<MapBase>` renderer ([src/components/MapBase.jsx](../../src/components/MapBase.jsx))
loads a self-hosted Protomaps **PMTiles** extract per city, served from this
directory at the app's own origin — no API key, no runtime third-party call. The
neighbourhood module requests:

```
/tiles/<cityId>.pmtiles
```

where `<cityId>` is the destination id (same ids as the destinations dataset).

## Expected files (mechanism PR — the two seed cities)

| File               | City   | Tier    | Needs tiles? |
| ------------------ | ------ | ------- | ------------ |
| `hav.pmtiles`      | Havana | full    | **yes** — renders the map |
| `sjo.pmtiles`      | San José | minimal | no — minimal tier is a text callout, no map |

Only **full-tier** cities render a map, so only `hav.pmtiles` is required for
this PR. Drop it here and the base appears automatically.

## Graceful absence

When an extract is missing (the state of this repo until the files are added),
`<MapBase>` probes the PMTiles header first and **degrades to a styled backdrop**:
the neighbourhood polygons, anchor marker and legend still render, just without
streets underneath, and the console stays quiet (no 404 noise). OSM + Protomaps
attribution appears **only** once a real extract loads.

## Producing an extract

Each file is a small area extract of the public Protomaps basemap build, e.g.
with the `go-pmtiles` CLI:

```bash
pmtiles extract https://build.protomaps.com/<date>.pmtiles hav.pmtiles \
  --bbox=-82.46,23.08,-82.33,23.16
```

Keep each extract tight to the city (a small bounding box around the anchor and
its areas) so the committed asset stays a few MB. These binaries are **not**
generated by the build; they are dropped in here and served as static assets.
